# Шпаргалка разработчику сайта (On-Chain State)

Версия 2026-10-05 · контракт v4.1 · сеть mainnet. Источник правды по инструкциям, аккаунтам и ошибкам — файл `idl/onchain_state_solana.json`; по состоянию проекта — `docs/HANDOFF_2026-10-04.md`. Вопросы по контракту — Роману (он передаёт агенту, который знает код). Всё ниже проверено на живом запуске 04.10.2026 (Test 2), а не придумано.

## 0. Десять вещей, на которых ломаются сайты с этим контрактом
1. **Сайт ничего не решает.** Все правила проверяет контракт; интерфейс только показывает и собирает транзакции. Кнопки «только для владельца» защищает контракт, а не интерфейс (прячьте их для удобства, но не полагайтесь на это).
2. **Суммы — большие целые, только `BigInt`/`BN`.** Выпуск 1 млрд монет × 10⁹ = 10¹⁸; уже 27,7 млн монет = 2,77·10¹⁶ — выше 2⁵³ (≈9·10¹⁵), `Number` теряет точность. Никогда не парсить суммы в `Number`, форматировать из `BigInt`.
3. **Сеть рвётся — это норма.** Любое чтение и любая отправка должны переживать `fetch failed`, `ECONNRESET`, 429, -32004. Рецепт в разделе 5. Сегодня при реальном запуске такие обрывы случились дважды; один раз транзакция `create_proposal` попала в сеть, а клиент получил ошибку — повтор «в лоб» создал бы дубль.
4. **Время — по часам цепи, не браузера.** Читать sysvar Clock (`SysvarC1ock11111111111111111111111111111111`, `unix_timestamp` — 8 байт со смещения 32, int64 LE) и считать смещение к `Date.now()`. `getBlockTime(слот)` на только что созданном слоте падает (-32004).
5. **Не опрашивать RPC на каждого посетителя.** Тестовая панель делает около 10–15 запросов каждые 8 секунд на открытую вкладку — для публичного сайта это сожжёт лимиты и деньги. Читать через кэш-прокси (раздел 6), опрос 20–60 с и только на видимой вкладке. Никаких `getProgramAccounts` у посетителей (стоит 10 кредитов, лимит 5–25/с).
6. **Две разные токен-программы.** Монета государства — **Token-2022**; казна, выплаты и пул (актив B) — **классический Token** (wSOL). Перепутать `programId` при расчёте ATA или чтении счёта — самая частая ошибка.
7. **Голосовать можно только тем, кого владелец внёс в список ДО открытия голосования.** Вес голоса = вес из снимка (`VoterSnapshot.weight`), не текущий баланс; монеты, купленные позже, и перекладывание между кошельками голосов не добавляют. Интерфейс обязан это объяснять («вас нет в списке голосующих по этому предложению»).
8. **Параметры (сроки, пороги, лимиты, зарплаты) читать только из `Config`.** Они меняются голосованием — хардкодить числа из этой шпаргалки нельзя.
9. **Ошибки контракта — по имени и простыми словами** (таблица в разделе 11), ошибки сети — отдельным спокойным сообщением («Сеть тормозит, повторяем…»), не как «ошибка».
10. **Ключи.** Сайт никогда не просит seed/приватный ключ; в боевом сайте нет тестовых «burner»-кошельков; ключ RPC в браузерном коде виден всем — ограничить по домену или спрятать за прокси.

## 2. Что читать и откуда (по экранам)
- **Обзор (публичный, без кошелька):** один `fetch` аккаунта `Config` — роли (`owners_authority`, `admin_authority`, `president`, `finance_minister`, `culture_minister`; пустая роль = `11111111111111111111111111111111`), параметры, `paused`, счётчики. Баланс казны — токен-счёт `treasury`. Монета: Mint (выпуск, знаки) + метаданные из самого mint (Token-2022 `TokenMetadata`: name/symbol/uri; **uri может быть пустым** — показывать заглушку, JSON и картинку тянуть с таймаутом и запасным вариантом).
- **Пул и «налог»:** через `@meteora-ag/cp-amm-sdk` (`fetchPoolState`, `fetchPositionState`, `getUnClaimLpFee`). Налог, ждущий сбора в казну = `getUnClaimLpFee(pool, position).feeTokenB`; доля Meteora (`protocolBFee`) не наша — не складывать с казной. Цена, SOL за монету = `(sqrtPrice / 2^64)^2` (оба знака по 9), оценка выпуска = цена × выпуск. SOL в хранилище пула B **включает** ещё не собранную комиссию — не выдавать за «ликвидность».
- **Оборот** точно считать нельзя из состояния; приблизительно (пока позиция государства = 100% ликвидности и комиссия плоская): оборот ≈ (собрано в казну + ждёт сбора) / 0,04. Для честной истории — события `evtSwap2` (индексатор/webhook), не пересчёт.
- **Предложения:** `proposalCount` из `Config`, затем `fetchMultiple` по PDA 0…n−1 (закрытые аккаунты вернут `null` — пропускать). Для подключённого кошелька — те же пакетом `VoterSnapshot` (`weight`, `consumed`).
- **Деньги:** `PayrollClaim` по ролям (`last_claim_ts`), `SpendTracker` (окна и потраченное), `Config.treasury_snapshot_amount` (см. формулы).
- **Вехи:** `Config.next_milestone_number`, `MilestoneRecord`, `MilestoneSnapshot` кошелька, фонд вех.
- **«Я»:** баланс монеты (ATA Token-2022), SOL, роли кошелька (сравнить с `Config`), доля от «голосующей базы».
- Читать пачками (`getMultipleAccounts` ≤100 адресов, `fetchMultiple` в Anchor), после своей транзакции — перечитать затронутые аккаунты (не считать, что всё получилось).

## 3. Формулы для отображения (точно как в контракте)
```
голосующая база сейчас  = выпуск − баланс счёта quorum_excluded_account (монеты в пуле не голосуют)
порог создания          : баланс_создателя × 10000 ≥ база × proposal_threshold_bps
кворум предложения      : (за + против) × 10000 ≥ base_at_open × quorum_bps   (база ЗАМОРОЖЕНА в open_voting)
quorum_bps по типу      : 0 и 6 → quorum_spend_bps; 1,2,3 → quorum_role_bps; 4,5 → quorum_param_bps
принято                 : кворум И за > против
дедлайн голосования     : proposal.deadline  (голосование идёт, пока now ≤ deadline)
исполнить можно с       : deadline + timelock_secs   (now ≥ этого и now > deadline)
исполнить можно до      : deadline + timelock_secs + exec_fallback_secs + 30 суток (потом ProposalExpired)
кто исполняет           : owner в любое время после «с»; президент — только после «с» + exec_fallback_secs
денежные (тип 0 и 6)    : не чаще раза в spend_cooldown_secs (last_spend_ts); трата ≤ 30% казны на момент создания И исполнения
зарплата роли           : выплата = treasury_snapshot × payroll_<роль>_bps / 10000; раз в 24 ч (last_claim_ts + 86400)
treasury_snapshot       : баланс казны на момент первой зарплаты/траты министра в текущие сутки (UTC) — не живой баланс
лимиты министра         : дневной/недельный = treasury_snapshot × <роль>_daily|weekly_bps / 10000; окна 24 ч / 7 сут от первой траты в окне
гражданин (вехи)        : вес × 10000 ≥ выпуск × citizenship_threshold_bps
```
Стадии предложения для интерфейса: «идёт запись избирателей» (`voting_open=false`) → «идёт голосование» → «кворум не набран» / «отклонено» → «принято, ждёт N» → «можно исполнять» → «просрочено» / «исполнено». Реализация — `stageOf()` в `web/src/pages/Proposals.tsx`. Типы: 0 трата, 1 президент, 2 финансовый министр, 3 культурный министр, 4 параметр (ключи 0–14 — список `PARAM_KEYS` в `chain.ts`), 5 смена owner, 6 пополнение фонда вех.

## 4. Что отправлять (кто, условия, подвох)
| Действие (инструкция) | Кто | Условия и подвохи |
|---|---|---|
| создать предложение `create_proposal` | любой держатель | баланс ≥ порога (формула выше); описание обязательно, ≤200 символов; трата ≤30% казны; **платит аренду** аккаунта предложения (несколько тысячных SOL, возвращается при закрытии; аренду снимков голосующих платит owner) |
| внести снимок `post_voter_snapshot` | **только owner** | по одному голосующему на транзакцию, owner платит аренду; вес ≤ баланса на момент записи; делается **один скан всех держателей** (иначе можно накрутить) |
| открыть голосование `open_voting` | только owner | нужен ≥1 снимок; после него снимки не принимаются; запускает таймер и замораживает базу |
| голосовать `vote(id, за/против)` | держатель со снимком | один раз; без снимка — `NoWeight`; до открытия — `VotingNotOpen` |
| исполнить `execute_proposal` | owner (президент позже) | см. формулы; **не работает при паузе** (любой тип); трата: счёт получателя (wSOL ATA) должен существовать и совпадать с `target`; пополнение фонда — передать счёт фонда |
| закрыть `close_proposal` / `close_voter_snapshot` | любой | после конца/исполнения; возвращает аренду создателю/owner |
| зарплата `claim_salary(роль)` | президент/министр | раз в 24 ч; **счёт wSOL получателя должен существовать** — создать идемпотентной инструкцией ATA в той же транзакции; потом предложить «вывести wSOL в SOL» (закрыть счёт) |
| трата министра `minister_spend(роль, сумма, причина)` | министр | в пределах дневного/недельного лимита (ошибки `ExceedsDailyLimit`/`ExceedsWeeklyLimit`); счёт получателя должен существовать; причина обязательна |
| собрать налог в казну `claim_pool_fees` | **любой** | получатель зашит в контракте — безопасно давать кнопку всем; пауза не блокирует; платит только комиссию сети |
| вехи: `create_milestone` → `post_milestone_snapshot` → `finalize_milestone` | owner | граждане: вес ≥ порога; предыдущая веха должна быть закрыта |
| `claim_milestone` | **любой платит**, получает гражданин | подпись гражданина не нужна — владелец/команда «рассылает» выплаты; выплата в активе казны (wSOL) на счёт гражданина |
| пауза `set_pause`, порог гражданина `set_citizenship_threshold` | только admin | пауза останавливает все выплаты и исполнения |
Запуск государства (`initialize`, `register_pool`, `setup_milestone_fund`), создание монеты и пула — делаются скриптами, **не публичным сайтом**. Покупка/продажа монеты — на Meteora/Jupiter (ссылка) либо встроенный своп через Meteora SDK: `getQuote({slippage})` принимает **базисные пункты** (не проценты), комиссия пула 5% плоская и уже внутри суммы.
Аренда/комиссии (измерено на mainnet): комиссия сети 0,000005 SOL; счёт wSOL 0,00148844 SOL; 8 предложений вместе со снимками ≈0,03 SOL (≈0,0035 SOL на предложение). Кошельку без SOL ответ — понятное «нужно немного SOL на комиссию», а не сырая ошибка.

## 5. Отправка транзакций и повторы (главное про обрывы)
**Чтение:** повтор до 3–5 раз с нарастающей паузой (0,3 → 0,6 → 1,2 → 2,4 с + случайный разброс); на ошибки `fetch failed`, `ECONNRESET`, 429, 5xx, -32004; потом запасной RPC; пользователю — «сеть тормозит, повторяем…», не красный экран. Ошибку программы (`Custom`/`AnchorError`) не повторять.
**Отправка:**
1. Собрать транзакцию, добавить свежий blockhash, **подписать один раз** в кошельке (`signTransaction`).
2. Отправлять самому: `sendRawTransaction(bytes, { maxRetries: 0 })`, затем цикл каждые ≈2 с: **та же подписанная транзакция** отправляется снова + `getSignatureStatuses([sig])`. Повтор одной и той же подписи безопасен (дубля не будет).
3. Подтверждение — **опросом статуса по HTTP**, не через websocket (`confirmTransaction` по умолчанию на публичных RPC зависает/режется).
4. Статус `confirmed` + нет `err` → успех. Есть `err` → показать понятную ошибку.
5. Если `getBlockHeight` > `lastValidBlockHeight` и подпись не найдена — транзакция уже никогда не пройдёт: **только теперь** собрать НОВУЮ (новый blockhash; кошелёк попросит подпись заново).
6. **Перед новой попыткой неидемпотентного действия** (создать предложение, проголосовать, собрать, получить зарплату) **перечитать состояние**: прошлая попытка могла дойти. Хранить «ожидающее действие» (ожидаемые адреса/id) в `localStorage`, чтобы после обновления страницы не создать дубль.
7. Перед подписью — `simulateTransaction`: так человек видит имя ошибки контракта, а не «кошелёк отказал»; не отправлять с `skipPreflight`, кроме специальных случаев.
8. Для важных действий в перегруженной сети — небольшая приоритетная комиссия (`ComputeBudgetProgram.setComputeUnitPrice`, лимит единиц ≈200–400 тыс.); у нас обычные транзакции проходили и без неё.
Цепочки из нескольких шагов (запись избирателей → открыть → голосовать) должны быть **возобновляемы**: сегодня обрыв случился между `create_proposal` и записью снимка — предложение осталось в сети «недостроенным». Интерфейс должен показывать состояние «идёт запись избирателей» и давать продолжить, а не создавать новое.

## 6. RPC и нагрузка
- Публичный `api.mainnet-beta.solana.com` — только для тестов (лимиты, обрывы, 429). Для сайта нужен платный/выделенный RPC. Цены Helius на 05.10.2026 (helius.dev/pricing): Free $0 — 1 млн кредитов/мес, 10 запросов/с, 1 `sendTransaction`/с, `getProgramAccounts` 5/с; Developer $49/мес — 10 млн, 50/с, 5 `sendTransaction`/с, gPA 25/с; Business $499/мес — 100 млн, 200/с; доп. кредиты $5 за млн. Обычный запрос = 1 кредит, `getProgramAccounts` = 10.
- **Схема:** маленький серверлесс-прокси (Cloudflare Worker): (а) раз в 20–30 с сам читает состояние из RPC и отдаёт всем посетителям как кэшированный JSON — стоимость не растёт с числом людей; (б) пропускает наружу только разрешённые методы RPC (`sendTransaction`, `getLatestBlockhash`, `getSignatureStatuses`, `simulateTransaction`, `getAccountInfo`, `getMultipleAccounts`, `getBalance`, `getBlockHeight`) с ограничением частоты на IP — так ключ RPC не светится в браузере. Альтернатива без прокси: ключ, ограниченный по домену в панели провайдера (хуже: домен можно подделать).
- Список держателей (нужен owner-панели для записи избирателей) — отдельная тяжёлая операция по требованию (gPA по mint или DAS/индексатор), не на каждого посетителя; поддержать пропуск «пыли» (минимальный вес).
- Запасной RPC на случай падения основного (хотя бы публичный) — с авто-переключением.

## 7. Числа, время, формат
- Всё в «сырых» единицах: монета и wSOL по 9 знаков; форматировать из `BigInt` (целая часть и остаток строкой). Ввод пользователя «0,3» → строкой в `BigInt` без `Number`/`parseFloat`.
- Проценты/bps: показывать % с двумя знаками из bps.
- Время контракта — unix-секунды цепи; для таймеров: `серверное_время ≈ Date.now()/1000 + смещение_цепи`. Показывать «исполнить можно с … (через N ч)» с запасом в пару минут: часы цепи могут отставать от настенных на несколько секунд.
- Локаль RU, часовой пояс пользователя + явная метка.

## 8. Кошельки и безопасность
- Wallet Standard / `@solana/wallet-adapter` (Phantom, Solflare, Backpack…); мобильные кошельки — через deep link/встроенный браузер, проверить размер транзакций.
- Подписывать только **понятные** транзакции: перед подписью показать человеческое резюме (что, сколько, кому, сколько SOL уйдёт на аренду/комиссию).
- Режим владельца: отдельный маршрут/приложение с баннером «режим владельца · сеть mainnet»; ключ владельца — аппаратный кошелёк. Один ключ (owner = admin = президент = upgrade authority) значит: потеря/кража ключа = потеря управления; UI это не исправит.
- Защита самого сайта: двухфакторка на хостинге/домене/GitHub, закреплённые версии зависимостей (lockfile), строгие заголовки (CSP), никакого стороннего JS без необходимости; подмена сайта — главный вектор атаки на крипто-проекты.
- Новый домен/программа могут вызывать предупреждения в Phantom/Solflare; не обещать, что они исчезнут (у кошельков своя проверка).
- Не писать «аудировано»/«безопасно»: внешнего аудита нет; показывать честное «версия программы, адрес, ссылка на код/обозреватель».
- Баннер сети (mainnet/devnet) и проверка, что подключённая сеть = ожидаемой.

## 9. Краевые случаи, которые надо обработать
- **Пауза** (`Config.paused`): баннер; зарплаты, траты министров, исполнение, выплаты вех — недоступны; сбор налога работает.
- **Аккаунт не декодируется** (старая версия формата, чужой аккаунт): не падать всей страницей, показать «неподдерживаемая запись». При обновлении программы IDL обновить вместе с ней (в v4→v4.1 изменился формат `Proposal`).
- Закрытые предложения исчезают (`null`); `proposalCount` только растёт.
- Нет метаданных/картинки у монеты; пул ещё не привязан (`fee_pool` = пусто) — показывать «пул не подключён».
- Пустые роли (министры не назначены); все роли должны быть разными адресами.
- Монеты вне пула = «голосующая база»: сразу после «дев = 0» запуска она почти ноль, первые покупатели и есть электорат — объяснять людям, а не удивляться 100% явке у одного человека.
- Приостановленные/просроченные предложения, кворум не набран — отдельные понятные статусы.
- До открытия торгов покупка в пуле отклоняется (`SwapDisabled`); часы цепи чуть отстают.

## 10. Среда разработки
- **devnet** — программа `3cbH…` и Meteora там есть; можно поднять полное тестовое государство с пулом. **Testnet не годится** (нет Meteora; старый сайт Никиты на testnet — v3, несовместим).
- **Локальный валидатор** с клоном Meteora (команда в `CLAUDE.md`, раздел «Как запускать») — быстрые сроки голосования (мастер тестовой панели ставит «Быстрый» набор: голосование 30 с).
- Для экранов владельца нужно свое тестовое государство, где ваш кошелёк — owner/admin/президент: мастер на вкладке «Настройка» тестовой панели или попросить Романа создать на devnet (нужен только адрес вашего тестового кошелька).
- Живые данные на mainnet для проверки отображения: Test 2 (адреса в разделе 1) — читать можно сразу; писать на mainnet — только малыми суммами и по согласованию.

## 11. Тексты ошибок контракта (имя → что сказать человеку)
Код = 6000 + номер; в логах/кошельках встречается как `custom program error: 0x17xx` (hex). Anchor отдаёт `error.errorCode.code` — маппить по имени из IDL.
| Имя | Человеческий текст |
|---|---|
| NotOwner / NotAdmin | Это действие доступно только владельцу / администратору |
| Paused | Выплаты из казны приостановлены (пауза) |
| ReasonRequired / ReasonTooLong | Нужно описание / описание длиннее 200 символов |
| ParamOutOfBounds / InvalidParamKey / InvalidProposalType / InvalidBps | Недопустимое значение или тип предложения |
| BelowThreshold | Недостаточно монет для создания предложения (нужна доля от монет вне пула) |
| ExceedsSpendCap | Сумма больше 30% казны |
| ExceedsMilestoneDepositCap | Сумма больше лимита пополнения фонда вех |
| InsufficientTreasury | В казне нет столько денег |
| ProposalNotActive | Голосование уже закончилось |
| ProposalStillActive | Голосование ещё идёт |
| VotingNotOpen | Голосование ещё не открыто (владелец должен внести список и открыть) |
| VotingAlreadyOpen | Голосование уже открыто — список голосующих закрыт |
| NoWeight / NoSnapshots | Вас нет в списке голосующих по этому предложению / в списке никого нет |
| WeightExceedsBalance / SnapshotWeightExceedsSupply | Вес в списке больше баланса / сумма весов больше выпуска |
| AlreadyVoted | Вы уже проголосовали |
| QuorumNotReached | Не набран кворум |
| ProposalRejected | Предложение не принято (против не меньше, чем за) |
| TimelockNotElapsed | Ожидание после голосования ещё не прошло |
| ProposalExpired | Предложение просрочено, исполнить нельзя |
| AlreadyExecuted | Уже исполнено |
| SpendCooldown | Недавно уже была трата — подождите |
| WrongRecipient | Получатель не совпадает с утверждённым |
| NotEligibleForPayroll / NotMinister | Вы не президент/министр |

Сетевые тексты: «нет SOL на комиссию» (`insufficient funds`, `Attempt to debit an account but found no record of a prior credit`), «подпись отклонена в кошельке», «сеть не успела подтвердить, повторяем», «программа не найдена в этой сети».
