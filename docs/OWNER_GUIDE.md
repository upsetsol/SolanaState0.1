# Руководство: как запустить и потрогать контракт руками (devnet, версия v4)

Для того, кто получил доступ к репозиторию и хочет сам всё инициализировать и посмотреть,
как работает контракт. Актуальная версия (**v4**: комиссия пула Meteora вместо налога токена) стоит на **Solana devnet**
(на testnet лежит прежняя v3 с налогом: для неё см. руководство в ветке `main`; на testnet нет программы Meteora, поэтому пул там не работает):

```
Program ID: FG7YYNJpcUHfHztKVou8yTLhZPntL6iR8fkRocW4oQdy
Обозреватель: https://explorer.solana.com/address/FG7YYNJpcUHfHztKVou8yTLhZPntL6iR8fkRocW4oQdy?cluster=devnet
```
Руководство лежит в ветке `pool-fees`: `git clone ...` затем `git checkout pool-fees`.

## Как это устроено (главное)

- **Программа одна, экземпляров государства — сколько угодно.** Каждое «государство» = свой токен
  (mint) + своя запись `Config`, привязанная к этому токену. Поэтому ничего деплоить не нужно:
  вы создаёте **свой тестовый токен** и инициализируете **своё государство** на уже стоящей программе.
  Вы будете в нём owner'ом, и управлять им сможете только вы (ключом своего кошелька).
- Код программы (upgrade authority) остаётся у того, кто её задеплоил. Вам он для тестов не нужен.
- Всё происходит на тестовой сети: SOL и токены там бесплатные и ничего не стоят.
- **Никогда не отправляйте кому-либо приватный ключ кошелька** (файл `owner.json`), даже помощнику
  и даже Claude в чате. Достаточно публичного адреса (`solana address`).

## 0. Доступ

1. Принять приглашение в репозиторий (письмо от GitHub на почту → Accept).
2. Скачать код:
   ```bash
   git clone https://github.com/upsetsol/SolanaState0.1.git
   cd SolanaState0.1
   ```
   (репозиторий закрытый, при запросе пароля используется GitHub-токен с правом `repo`,
   создаётся в GitHub → Settings → Developer settings → Personal access tokens.)

## 1. Установка (один раз)

- **Node.js** 20 или новее (https://nodejs.org).
- **Solana CLI** (https://docs.solana.com/cli/install): нужна только команда `solana` для кошелька.
- Зависимости проекта:
  ```bash
  npm install
  ```
Rust и Anchor **не нужны**: описание контракта уже лежит в `idl/onchain_state_solana.json`.

## 2. Свой кошелёк и тестовые SOL

```bash
solana-keygen new -o ~/owner.json          # создать кошелёк (запомните seed-фразу, ключ никому не отправлять)
solana config set --url devnet
solana config set --keypair ~/owner.json
solana address                              # ваш публичный адрес
```
Тестовые SOL: https://faucet.solana.com → выбрать **Devnet** → вставить адрес. Нужно около **2–3 SOL**
(запросить можно несколько раз; если кран отказывает по лимиту, попробуйте позже). Проверка: `solana balance`.

Публичный devnet иногда тормозит и обрывает соединения: если транзакция не проходит (`Blockhash expired`, `429` и т.п.),
просто повторите команду. Для стабильной работы лучше завести бесплатный ключ у провайдера RPC (например Helius) и
подставить его адрес вместо публичного; ключ храните только в переменной окружения.

## 3. Общие настройки терминала

Выполняйте в каждом новом окне терминала (в папке проекта):
```bash
export ANCHOR_PROVIDER_URL=https://api.devnet.solana.com     # или ваш RPC-адрес
export ANCHOR_WALLET=~/owner.json
```

## 3.5. Веб-интерфейс (проще всего)

Вместо команд можно работать через сайт, который читает настоящее состояние контракта:

```bash
cd web
npm install
npm run dev        # откройте http://127.0.0.1:5173
```
Вкладка «Настройка» → выбрать Devnet → «+ Тестовый кошелёк» → получить SOL (кнопка Airdrop или faucet.solana.com) → пройти мастер
(токен, инициализация, SOL в казну для теста, фонд вех, привязка пула Meteora; сам пул создаётся скриптом `create_pool.ts`). Дальше вкладки «Предложения», «Деньги», «Вехи», «Админ». Подробности: `web/README.md`.

## 4. Быстрый способ увидеть всё сразу

```bash
npx ts-node scripts/e2e.ts
```
Скрипт сам создаёт монету государства, инициализирует государство (казна в wSOL), раздаёт монеты трём тестовым
холдерам и прогоняет **все** сценарии (голосование, зарплаты, лимиты, вехи, пауза, пул Meteora и сбор комиссии в казну…),
печатая ✅/❌ по каждому. Идёт 10–15 минут (там есть ожидания). Часть про пул выполняется, только если на сети есть
программа Meteora (есть на devnet и mainnet, на testnet её нет: тогда этот шаг пропускается). Тратит около 1 SOL.
Лучший способ понять, что вообще умеет контракт.

## 5. Своё государство по шагам (руками)

```bash
# 1. Своя монета государства: Token-2022 с названием и символом, БЕЗ налога, 1 млрд монет на ваш кошелёк
NAME="Test 1" SYMBOL=TEST1 INITIAL_SUPPLY=1000000000 npx ts-node scripts/create_mint.ts
export GOVERNANCE_MINT=<адрес токена из вывода>
# Актив казны по умолчанию wSOL (обёрнутый SOL). Для USDC/USDT: export TREASURY_MINT=<mint>

# 2. Инициализация: вы и owner, и admin, и первый президент (PARAMS=test = короткие сроки)
ME=$(solana address)
OWNERS_AUTHORITY=$ME ADMIN_AUTHORITY=$ME PRESIDENT=$ME PARAMS=test npx ts-node scripts/initialize.ts

# 3. Фонд вех (для наград гражданам)
npx ts-node scripts/setup_milestone_fund.ts

# 4. Пул Meteora: 5% комиссия с каждой покупки и продажи, только в SOL; ликвидность блокируется навсегда,
#    позиция передаётся государству (нужен devnet или mainnet: на testnet программы Meteora нет).
#    Делайте это ДО раздачи монет другим людям: адрес пула зависит только от пары токенов.
TOKEN_AMOUNT=100000000 QUOTE_AMOUNT=1 npx ts-node scripts/create_pool.ts
npx ts-node scripts/register_pool.ts

# 5. Торговля (можно с другого кошелька: KEYPAIR=~/trader.json) и сбор комиссии в казну (может вызвать любой)
SIDE=buy AMOUNT=0.1 npx ts-node scripts/pool_swap.ts
npx ts-node scripts/claim_pool_fees.ts

# 6. Посмотреть состояние
npx ts-node scripts/inspect.ts
```
Для теста голосования без пула казну можно наполнить вручную: `AMOUNT=1 npx ts-node scripts/fund_treasury.ts` (1 SOL заворачивается в wSOL на счёт казны).
Сроки в режиме `test`: голосование 5 минут, ожидание перед исполнением 1 минута, пауза между тратами
2 минуты. Боевые значения (`PARAMS=prod`) в `scripts/params.ts`.

### Пример: потратить деньги казны через голосование

```bash
npx ts-node scripts/propose_and_vote.ts      # создаёт предложение «потратить», вносит ваш снимок, голосует «за»
# подождать ~6 минут (5 минут голосования + 1 минута ожидания)
npx ts-node scripts/execute_proposal.ts 0 --spend
```
(`0` — номер предложения, вывод первой команды покажет номер.)

Чтобы голосовали другие люди, им нужны монеты государства: перевести с вашего кошелька (`spl-token` или свой скрипт),
после чего вы вносите их снимок командой `postSnapshot` (в `scripts/lib/env.ts`) **до первого голоса**.

## 6. Что за что отвечает

| Действие | Кто | Скрипт |
|---|---|---|
| Создать монету государства | любой | `create_mint.ts` |
| Создать государство | кто платит; получает роли из параметров | `initialize.ts` |
| Положить актив в казну (тест) | любой | `fund_treasury.ts` |
| Создать пул Meteora и передать позицию государству | эмитент | `create_pool.ts` |
| Привязать пул к государству (один раз) | owner | `register_pool.ts` |
| Купить / продать в пуле (тест) | любой | `pool_swap.ts` |
| Создать фонд вех | owner | `setup_milestone_fund.ts` |
| Состояние | любой | `inspect.ts` |
| Создать предложение | холдер | `propose_and_vote.ts` (пример «всё в одном» для одного кошелька), `change_param.ts`, `appoint_minister.ts`, `appoint_culture_minister.ts`, `change_president.ts`, `change_owners_authority.ts` |
| Внести избирателей: один скан → готовые веса (v4.1) | owner | `snapshot_all.ts` (`PROPOSAL_ID=…`, `OPEN=1` — заодно начать голосование) |
| Начать голосование (заморозить базу кворума) | owner | `open_voting.ts` (`PROPOSAL_ID=…`) |
| Пополнить фонд вех (через голосование) | холдер | `deposit_to_milestone_fund.ts` |
| Исполнить решение | owner (президент — через сутки, если owner молчит) | `execute_proposal.ts` |
| Зарплата | президент/министры | `claim_salary.ts` |
| Трата министра | министр | `minister_spend.ts` |
| Забрать накопленную комиссию пула в казну | любой | `claim_pool_fees.ts` |
| Веха: создать → снимки → закрыть | owner | `test_milestone.ts` |
| Выплата гражданину по вехе | owner | `claim_milestone.ts` |
| Вернуть остатки вехи в фонд | owner | `release_milestone_reserve.ts` |
| Пауза / порог гражданина | admin | `set_pause.ts`, `set_citizenship_threshold.ts` |
| Проверки «должно упасть» | любой | `test_*.ts` |

Параметры скриптов описаны в комментариях в начале каждого файла.

## 7. Где смотреть результат

- В терминале: `inspect.ts` (настройки, роли, лимиты, резерв вех).
- В обозревателе: вставить адрес транзакции (печатается после каждой команды) на
  https://explorer.solana.com/?cluster=devnet. Видно, что и когда произошло.

## 8. Если вы работаете через Claude Code

Откройте папку проекта в Claude Code и напишите, например:

> Прочитай README.md, OPEN_ITEMS.md и docs/OWNER_GUIDE.md. Я хочу на devnet поднять своё государство
> и по шагам пройти сценарий «голосование за трату». Мой кошелёк ~/owner.json, сеть devnet.
> Веди меня по шагам и объясняй, что делает каждая команда.

Claude прочитает код, запустит нужные скрипты и объяснит результат. Приватный ключ ему не отправляйте
(достаточно пути к файлу на вашем компьютере).
