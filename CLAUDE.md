## Что делает контракт v4 (кратко; детали в README.md и OPEN_ITEMS.md)
- Program ID `FG7YYNJpcUHfHztKVou8yTLhZPntL6iR8fkRocW4oQdy`, один файл `programs/onchain-state-solana/src/lib.rs` (~2100 строк), Anchor 1.1.2.
  Одна программа, много «государств» (по одному на `governance_mint`; Config PDA = `["config", governance_mint]`).
- **Две монеты:** `governance_mint` (Token-2022 + метаданные, **без налога**) даёт только голос; `treasury_mint` (по умолчанию wSOL, USDC/USDT параметром)
  — казна, зарплаты, лимиты министров, траты, фонд вех, выплаты.
- **Казну наполняет пул Meteora DAMM v2**: постоянная комиссия 5% только в парном активе (режим `OnlyB`), берётся в самой сделке. Ликвидность
  блокируется навсегда, NFT позиции держит Config PDA. `register_pool` (owner, один раз) проверяет пару токенов/режим/владельца позиции ончейн;
  `claim_pool_fees` (**любой**, permissionless) забирает накопленное **только** на счёт казны (адрес зашит в контракте).
- Meteora забирает **20%** комиссии (казне ≈4% оборота при 100% нашей ликвидности); **посторонний может добавить ликвидность без разрешения**
  и делит комиссию пропорционально доле; создатель пула комиссию менять не может (только операторы Meteora).
- Кворум и порог создания предложения считаются от выпуска монеты государства **минус монеты в хранилище пула** (`quorum_excluded_account`,
  ставится в `register_pool`); после регистрации это хранилище нужно передавать в `create_proposal`/`execute_proposal`.
- Правила v3, сохранённые: вес голоса = реальный баланс (снимки постит owner до первого голоса), timelock на все типы, исполняет owner
  (президент через `exec_fallback_secs`), роли — разные адреса, «утренний снимок» казны для зарплат/лимитов, лимиты министров по роли,
  фонд вех (тип предложения 6) с резервом и возвратом остатка, `spend_cooldown_secs`, пауза и порог гражданина у `admin_authority`.
- **Кастомный** пул Meteora для пары токенов один (адрес зависит только от пары): создавай его **до раздачи монет**, иначе держатель может создать «свой» раньше.
  Но **параллельные пулы** той же пары любой держатель может открыть из публичных конфигов Meteora (на mainnet 152 «обычных», комиссия от 0,25%; проверено
  тестом `audit/a5_competing_pool.ts`) — казна получает комиссию только с нашего пула (аудит, находка №6).
- Meteora DAMM v2 (`cpamdpZCGKUy5JxQXB4dcpGPiikHawvSWAd6mEn1sGG`) есть на **mainnet и devnet, на testnet нет**.

## Как запускать
```bash
anchor build                                   # .so + IDL; после изменений: cp target/idl/onchain_state_solana.json idl/
# локальный валидатор с нашей программой и КЛОНОМ Meteora (нужен интернет к devnet)
solana-test-validator --reset --ledger <dir> \
  --bpf-program FG7YYNJpcUHfHztKVou8yTLhZPntL6iR8fkRocW4oQdy target/deploy/onchain_state_solana.so \
  --clone-upgradeable-program cpamdpZCGKUy5JxQXB4dcpGPiikHawvSWAd6mEn1sGG --url https://api.devnet.solana.com &
solana --url http://127.0.0.1:8899 airdrop 1000 <кошелёк>
ANCHOR_PROVIDER_URL=http://127.0.0.1:8899 ANCHOR_WALLET=~/.config/solana/id.json npx ts-node scripts/e2e.ts      # ~10 мин
# реальная сеть: E2E_SLOW=1 (окна 75 с; HTTP-подтверждения без websocket; время из Clock sysvar) и ЛЮБОЙ надёжный RPC
cd web && npm run dev                          # сайт; UI-тест: node tests/ui-e2e.mjs (dev-сервер на 127.0.0.1:5173)
```
Сценарии из консоли для Никиты: `docs/OWNER_GUIDE.md` (create_mint → initialize → setup_milestone_fund → create_pool → register_pool → pool_swap → claim_pool_fees).
Загрузка/обновление программы по нестабильному RPC: `scripts/upgrade_program.ts` (дописывает недостающие куски буфера, сверяет побайтно, обновляет).

  заменяется одной транзакцией `Upgrade` после полной записи буфера (обрыв посреди — старая версия продолжает работать, SOL лежит в буфере и возвращается
  `solana program close --buffers`). На время обновления кошельку нужно ≈ **2,47 SOL** (буфер, вернётся) + плата за лишние байты, если новый `.so` **больше**
  486 888 Б (сегодняшняя ёмкость; 5080 lamports/байт ≈ 0,0052 SOL за КБ) + комиссии. `solana program deploy` докупает место сам (флаг `--no-auto-extend` выключает —
  тогда ошибка «ProgramData account not large enough»); `scripts/upgrade_program.ts` сам НЕ расширяет — сначала `solana program extend`. Депозит не уменьшается, даже если файл
  потом станет меньше. Сейчас на кошельке `A7mn…` на mainnet 0,0688 SOL (30.09) — для обновления пополнить. На mainnet под программой **один** аккаунт — Config «Test 1»
  (чужих государств нет). Если формат `Config`/`Proposal` изменится, Test 1 станет нечитаемым для нового кода (монета и пул останутся, управлять ими будет нельзя) — для теста не
  страшно. Перед первым обновлением сохранить текущий байт-код: `solana program dump FG7Y… <файл>` (первые 486 888 Б = sha256 `5e138c88…7237`). Порядок: правки → тесты → репетиция
  обновления на devnet (тот же адрес) → mainnet.
- Даже на платном/надёжном RPC (Helius) реальная сеть иногда рвётся: `fetch failed`, `ws error: ECONNRESET`, JSON-RPC `-32004` («blockNotAvailable» —
  спросили время блока сразу после его номера, узел не успел). Это нормально и бывает у всех, не признак проблемы с нашим кодом или деньгами.
  Наши скрипты (`e2e.ts`) это переживают через `E2E_SLOW=1` и HTTP-повторы; **сайт пока умеет повторять только при истёкшем blockhash**

## Как работать (предпочтения пользователя, подтверждены по ходу)
- Русский, коротко, простыми словами; техническое объяснять «на пальцах»; не пугать, не приукрашивать; неопределённость называть прямо. Пересказы для Никиты давать текстом в чат.
- Длинные тексты «для Никиты»/шпаргалки — в чат или файлом (`SendUserFile`), **не в GitHub**, если пользователь не просил.
- Перед необратимым (удаление, закрытие программы, mainnet, траты SOL) — спросить. Автомат-классификатор блокирует пакетное удаление файлов: тогда отдать Роману команду для запуска в его терминале.
- Не выдумывать цифры: стоимость/размер/комиссии мерить (`solana rent`, RPC, тесты). Свои ошибки признавать сразу.

- В инструментах: `sleep` в foreground заблокирован — ждать через `Monitor`/фоновые `until`-циклы; в macOS нет `timeout`; `sed -i ''` (с пустой строкой); zsh раскрывает `=====`.
- Стек SBF 4 КБ: большие контексты аккаунтов `Box`-ить (иначе ошибка сборки `Stack offset exceeded`).
- Anchor 1.1.2: `anchor deploy` для апгрейда сломан (`ExtendProgram`), апгрейд — `solana program deploy <so> --program-id <keypair>` или `scripts/upgrade_program.ts`.
- Названия двух ошибок перепутаны (`ProposalNotActive` пишет «Voting period still active», а значит «голосование уже закончилось»; `ProposalStillActive` наоборот) — косметика.
- Список сайта: сайт читает **все** аккаунты программы (`.all()`), при нескольких государствах на одной программе фильтровать по PDA текущего государства (исправлено для вех).

слайдеров, эффективная ставка = fee% × 0.8 × доля%, не зависит от объёма — подтверждено). Пользователь заливает его
самостоятельно на свой Cloudflare Worker (`treasury-calculator.talaninromashkq.workers.dev`, отдельно от `web/`, без
