# Тестовая панель контракта (web)

Настоящий интерфейс к контракту: всё, что он показывает, читается из блокчейна, ничего не выдумано.
Покрывает все инструкции контракта. Предназначен для **тестовых сетей**.

## Запуск

```bash
cd web
npm install
npm run dev          # http://127.0.0.1:5173
```

Откройте вкладку **Настройка**: выберите сеть (testnet / devnet / локальный валидатор), создайте
тестовые кошельки, пройдите мастер (токен → инициализация → SOL в казну (для теста) → фонд вех → привязка пула Meteora). Дальше:

| Вкладка | Что можно |
|---|---|
| Настройка | сеть, кошельки (тестовые + Phantom), airdrop, перевод SOL и токенов, мастер запуска государства |
| Обзор | всё состояние из блокчейна: казна (SOL), фонд, роли, правила, лимиты, монета, пул Meteora |
| Предложения | создать (7 типов), снимки голосов, голосование, исполнение; статус считается теми же формулами, что в контракте |
| Деньги | зарплата, траты министров с лимитами (в активе казны), кнопка «Забрать комиссию» пула в казну |
| Вехи | создать, снимки граждан, закрыть, выплаты, возврат остатка |
| Админ | пауза, порог гражданина |

**Журнал действий** внизу показывает каждую транзакцию и ответ контракта. Отказы приходят с названием
ошибки (`NotOwner`, `SpendCooldown` и т.д.).

## Как тестировать

- **Тестовые кошельки** хранятся в браузере и подписывают без подтверждений. Переключатель
  вверху справа меняет, от чьего имени идут действия (owner, президент, министр, холдер).
  Так проверяются роли без Phantom.
- **Набор параметров «Быстрый»**: голосование 30 с, ожидание 10 с. Полный цикл занимает минуты.
- Галочка **«Отправлять без предварительной проверки»**: для проверки отказов на стороне контракта.
- **Пул Meteora** создаётся в консоли (`scripts/create_pool.ts`, см. корневой README): сайт его только привязывает
  (шаг 3.5), показывает накопленную комиссию и забирает её в казну. Для пула нужна программа Meteora на сети (devnet;
  на локальном валидаторе: `--clone-upgradeable-program cpamdpZCGKUy5JxQXB4dcpGPiikHawvSWAd6mEn1sGG --url devnet`).
- Для локального валидатора: `solana-test-validator --reset --bpf-program <PROGRAM_ID> target/deploy/onchain_state_solana.so`
  (+ клон Meteora, см. выше), затем в «Настройка» выбрать «Локальный валидатор» и нажать Airdrop у кошельков.

## Автотест интерфейса

Скрипт `tests/ui-e2e.mjs` управляет сайтом в Chrome и проходит весь сценарий против
локального валидатора: создание токена, голосования, отказы контракта, роли, зарплаты, лимиты,
пауза, вехи, привязка пула Meteora и сбор его комиссии в казну (пул создаёт консольный скрипт).

```bash
solana-test-validator --reset --bpf-program <PROGRAM_ID> ../target/deploy/onchain_state_solana.so \
  --clone-upgradeable-program cpamdpZCGKUy5JxQXB4dcpGPiikHawvSWAd6mEn1sGG --url devnet &
npm run dev &
npm run test:ui       # нужен установленный Google Chrome
```

`tests/external-wallet.mjs` (`npm run test:wallet`) проверяет путь внешнего кошелька вроде Phantom на
поддельном кошельке: сайт обязан передать кошельку сеть, иначе Phantom симулирует транзакцию в другой
сети и показывает ложные красные предупреждения («not enough SOL», «failed to simulate»).

## Описание контракта (IDL)

Берётся из `../idl/onchain_state_solana.json`. После изменения программы:
`cp target/idl/onchain_state_solana.json idl/`.

## Безопасность

Тестовые кошельки хранят секретные ключи в `localStorage`. Только для тестовых сетей и без настоящих
средств. На mainnet тестовые кошельки отключены.
